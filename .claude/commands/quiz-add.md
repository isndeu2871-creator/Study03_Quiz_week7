# 문항 추가

`$ARGUMENTS`로 개수 `n`을 받아, 카테고리 4개(한국사, 세계지리, 과학, 예술과 문화)에 **각각 n개씩** 새 문항을 만든다. 모두 `4n`개다.

카테고리마다 같은 수를 넣는 까닭은 PRD 1절이 "카테고리마다 문항 수가 같음"으로 정하고 있어서다. 한 카테고리만 늘리면 Node 문항 검사가 걸린다.

`n`이 없거나 1 이상의 정수가 아니면, 쓸 방법을 알려 주고 멈춘다.

## 순서

### 1. 문항을 만든다 (파일은 고치지 않는다)

- 규칙은 `CLAUDE.md`의 문항 작성 규칙을 읽어서 지킨다. 규칙 본문을 이 파일에 옮겨 적지 않는다.
- 해설의 출처 표기와 길이는 `PRD.md`를 읽어서 따른다.
- `questions.js`의 기존 문항을 먼저 읽어, 이미 있는 주제·정답과 겹치지 않게 한다.
- id는 카테고리별 접두사(`kh`, `wg`, `sc`, `ac`)에 이어지는 번호를 쓴다(예: 한국사가 10개면 `kh-11`).

### 2. 출처를 실제로 열어 확인한다

- **서로 다른 기관 2곳**을 실제로 열어 값을 대조한다. 같은 문서의 번역판이나 같은 기관의 다른 페이지는 2곳으로 치지 않는다.
- 두 곳의 값이 어긋나면 **그 사실을 버리고 다른 주제로 바꾼다.** 어긋난 값을 문제나 해설에 쓰지 않는다.
- 쓰지 않는 곳: 위키백과, 나무위키, 개인 블로그. 정부·공공기관, 학술 기관, 사전·백과 기관, 언론사의 원문을 쓴다.
- 학계에 이견이 있는 주제는 피한다.
- `questions.js`의 `source`에는 2곳 가운데 근거가 더 분명한 **1곳만** 적는다. 이 저장소의 데이터 형식이 `source`를 문자열 1개로 정하고 있다(PRD 6절).
- `WebFetch`가 403으로 막히는 기관이 있다. 도구를 바꿔 열었으면 **그 사실을 보고에 먼저 밝힌다.** 끝내 열리지 않으면 그 출처를 포기하고 다른 기관으로 바꾼다.

### 3. 승인을 받는다

파일을 전혀 고치지 않은 상태에서 아래 둘을 보여 주고 **멈춰서 답을 기다린다.**

**(1) 문항 전문** — id, 카테고리, 문제, 보기 4개, 정답, 해설, source

**(2) 검수표**

| id | 출처 A (기관·주소) | 출처 B (기관·주소) | 두 곳이 일치 | source에 적을 곳 | 규칙 확인 |
|---|---|---|---|---|---|

- "두 곳이 일치" 칸으로 규칙 4를 눈으로 확인하게 한다.
- "규칙 확인" 칸에는 스스로 점검한 규칙 번호와 결과를 적는다.

### 4. 승인받은 것만 넣는다

- 전부 승인하면 `questions.js`에 넣는다.
- **일부만 승인하면, 거절한 문항은 새 주제로 다시 만들어 2~3단계를 되풀이한다.** 카테고리마다 문항 수가 같아야 하므로 일부만 넣으면 균형이 깨진다. 승인된 것만 먼저 넣지 않는다.
- 넣는 위치는 그 카테고리 문항들의 끝이다.

### 5. 넣은 뒤 확인하고 멈춘다

- `IMPL-PLAN.md` Task 1 Step 5의 Node 문항 검사를 실행한다. 통과 기준은 **마지막 줄이 `문항 검사 통과:`로 시작하고 종료 코드가 0**인 것이다. 문항 수를 못 박아 기대하지 않는다.
- `node script.js`를 실행한다. 통과 기준은 **마지막 줄이 `점검 통과:`로 시작하고 종료 코드가 0**인 것이다.
- 고친 파일과 더한 문항 수를 보고한다.
- **커밋하지 않는다.** 브랜치와 커밋, 병합은 사람이 한다.
